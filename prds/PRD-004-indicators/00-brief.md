# PRD-004 · Spot OHLCV and technical indicators

**In one to three sentences:** Compute the standard technical indicators — RSI, EMA stack,
MACD, StochRSI, Bollinger, ATR, OBV — for BTC, ETH, SOL and BNB, so the board carries **~32
real cells** instead of one. This is the first genuine scale test of everything built so far.

**Depends on:** PRD-002 (harness), PRD-003 (corroboration).

**Roughly:** 7–9 stories.

---

## Why this is the risky one

Everything to date is proven on **a single indicator on a single asset**. The claim that the
design scales is untested, and this PRD is where it either holds or buckles. Four specific
places it could:

1. **The bar-slice contract meets recursive indicators.** `btc_daily_close` needs exactly 1
   bar. RSI(14) with Wilder smoothing needs *far more* than 14 to converge, and "how many is
   enough" is a real question with a measurable answer — TA-Lib documents an *unstable period*
   for exactly this family (RSI, EMA, ATR, ADX, CMO, DX, KAMA, T3 among ~22). PRD-002 fixed the
   contract at "exactly N"; this PRD has to choose N per indicator and **justify it**.
2. **The registry grows from 1 entry to ~32.** Coverage generated from it (US-207) either holds
   or becomes noise.
3. **Four assets, not one.** `definable_for` stops being decorative — and SOL/BNB may not have
   the same history depth at every venue.
4. **Goldens need external oracles.** One published close was enough for PRD-002. Seven
   indicator families need hand-computed or reference vectors, and **that is where the real
   work in this PRD sits.** A golden generated by our own code proves only that we agree with
   ourselves — the exact trap that made US-006's wrong value look correct.

## What the harness already gives us

Not starting from nothing. Already built and proven: exactly-N-bar slices rejected at the
compute boundary, strict vendor models (`extra='forbid'`), truncation/gap/duplicate detection,
recorded fixtures, registry-generated coverage, a live drift canary, and corroboration between
OKX and Coinbase.

**Every indicator added here inherits all of it.** That was the whole argument for building the
harness first, and this PRD is the test of whether that argument was right.

## Explicitly NOT in this PRD

- No composite, no score, no signal, no ranking — permanently out of scope (G1).
- No derivatives, on-chain or macro. Those are PRD-006, 007, 008.
- No dashboard design — PRD-005 owns that, and it comes next precisely so it can be designed
  against these real cells.
- No indicator we cannot obtain an **external** golden for. Better a smaller honest board than
  a value that agrees only with itself.
- No new venue beyond OKX and Coinbase.

## The adversarial case this PRD must pass

Per `25_PRD_Acceptance_Protocol.md`: **check a computed indicator against a value computed
outside this codebase** — hand arithmetic or a published reference vector — not against our own
output. If RSI(14) on a fixed bar series matches an independently-derived number, the
computation is right. If it only matches itself, we have learned nothing.
